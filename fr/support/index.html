Support

Vous ne trouvez pas ce que vous cherchez ? Écrivez à support@veloworkspaces.com et nous vous aiderons directement.

Prise en main

Comment créer un espace de travail

  1. Choisir l'origine du système

    Choisissez une bibliothèque dans la barre latérale, puis cliquez sur « + » en haut à droite. Prenez « Image cloud » pour un système prêt à l'emploi en une minute environ, « Image d’installation » pour lancer l'installateur d'une distribution, ou « Démarrer à partir d'un disque virtuel existant » pour partir d'une image de base ou d'un disque que vous avez déjà.

  2. Choisir l'image

    Choisissez une distribution et une version. Les images sont téléchargées depuis les serveurs de l'éditeur dans votre bibliothèque d'images, vérifiées avec la somme de contrôle publiée, puis réutilisées la fois suivante. Vous avez déjà le fichier ? Cliquez sur « Choisir un fichier… ». Pour les installateurs d'Ubuntu, de Fedora Server et de Rocky Linux, laissez « Installation automatique » activée : l'installation se déroule toute seule.

  3. Configurer, vérifier et créer

    Choisissez un profil (Code & Build, DevOps Lab, AI Sandbox ou Office & Study) ou réglez vous-même processeur, mémoire et disque, puis saisissez un nom d'utilisateur et un mot de passe. Vérifiez le récapitulatif et cliquez sur « Créer l’espace de travail ». L'app crée votre compte et y ajoute la clé SSH de ce Mac.

Comment utiliser les espaces de travail jetablesPro

  1. Ajouter un espace de travail jetable

    Choisissez « Espace de travail jetable » dans la barre latérale, cliquez sur « + » en haut à droite et suivez les étapes ci-dessus. Le plus rapide : « Démarrer à partir d'un disque virtuel existant » avec une image de base enregistrée, pour un système fiable prêt en quelques secondes.

  2. L'utiliser pour exactement une tâche

    Lancez votre test, reproduisez le bug, ou essayez la commande risquée — traitez l'espace de travail comme entièrement jetable.

  3. Le fermer

    Fermer un espace de travail jetable le supprime automatiquement, disque compris. Il n'y a rien à nettoyer ensuite, et rien à récupérer — n'utilisez pas les espaces de travail jetables pour quoi que ce soit que vous devez conserver.

Questions fréquentes

Images cloud et installations automatiques

Quels systèmes Linux puis-je créer à partir d'une image cloud ?

Ubuntu 26.04 et 24.04 LTS, Debian 13 et 12, Fedora 44 Cloud Base, et Rocky Linux 10 et 9. L'app télécharge l'image officielle de l'éditeur, la convertit pour le framework Virtualization d'Apple et transmet à cloud-init votre nom d'utilisateur, votre mot de passe, la clé SSH de ce Mac et un nom d'hôte. Au premier démarrage, le système se configure seul et s'étend à la taille de disque choisie. Une fois le téléchargement terminé, il est en général prêt en une minute environ.

Quels installateurs peuvent tourner tout seuls ?

Ubuntu Server et Desktop, Fedora Server et Everything, et Rocky Linux (minimal et DVD). Laissez « Installation automatique » activée à l'étape Image : l'app répond aux questions de l'installateur avec votre compte, votre clé SSH, ainsi que la langue, le clavier et le fuseau horaire de ce Mac. L'installateur ne s'arrête pour aucune question, pas même avant d'effacer le disque virtuel. Une fois l'installation terminée, l'espace de travail redémarre sur le nouveau système.

Quels systèmes dois-je installer à la main ?

L'installateur de Debian, Fedora Workstation, Kali Linux, NixOS et Alpine Linux lancent leur propre installateur dans l'affichage de l'espace de travail, comme sur un PC. Pour une Debian sans intervention, utilisez plutôt l'image cloud Debian. Sur un Mac avec puce Apple, vous pouvez aussi installer macOS depuis l'image de restauration d'Apple.

Puis-je utiliser une ISO ou une image cloud déjà téléchargée ?

Oui. Cliquez sur Choisir un fichier… à l'étape Image, ou sur « Importer… » dans Réglages › Images. Si le nom du fichier figure dans la liste de sommes de contrôle de l'éditeur, l'app le vérifie avec la somme officielle avant de l'utiliser. Tout ce que vous téléchargez ou importez reste dans Réglages › Images (aussi « Images » dans la barre latérale), où vous pouvez le réutiliser, le vérifier ou le supprimer.

SSH et terminal

Comment ouvrir un terminal dans un espace de travail ?Pro

Démarrez l'espace de travail, ouvrez son onglet « Accès » et cliquez sur « Ouvrir le Terminal ». Le terminal intégré se connecte en SSH avec une clé que l'app a créée pour ce Mac et conserve dans votre trousseau. Les espaces de travail créés depuis une image cloud ou une installation automatique acceptent déjà cette clé.

Pour un système installé vous-même, saisissez son nom d'utilisateur dans l'onglet « Accès », connectez-vous une fois avec le mot de passe, puis cliquez sur « Installer la clé » : le mot de passe ne vous sera plus demandé. Vous pouvez copier, importer ou exporter la clé dans Réglages › Accès.

Puis-je utiliser mon propre terminal ou VS Code, ou me connecter depuis un autre ordinateur ?

Oui, et c'est gratuit. L'onglet « Accès » affiche l'adresse de l'espace de travail avec une commande ssh prête à copier, ainsi que le bloc ~/.ssh/config pour l'extension Remote - SSH de VS Code. Ils utilisent votre propre clé SSH, pas celle que le terminal intégré garde dans le trousseau : collez votre clé publique dans « Clés publiques SSH » en créant l'espace de travail, ou activez « Autoriser les connexions SSH avec le mot de passe ».

Les autres ordinateurs atteignent un espace de travail via votre Mac, car les espaces de travail se trouvent sur un réseau privé à l'intérieur. Activez « Session à distance » dans Réglages Système › Général › Partage, puis utilisez la commande ssh -J affichée dans l'onglet « Accès ».

Pourquoi macOS demande-t-il à Velo Workspaces l'accès aux appareils du réseau local ?

Les espaces de travail se trouvent sur un petit réseau virtuel à l'intérieur de votre Mac (adresses du type 192.168.64.x), que macOS considère comme le réseau local. La vérification SSH et le terminal se connectent à cette adresse, d'où la demande unique de macOS. L'app ne parcourt ni n'analyse jamais votre réseau ; elle ne parle qu'à ses propres espaces de travail.

Si vous avez refusé, l'onglet « Accès » affiche « Pas d’accès au réseau local ». Réactivez l'accès dans Réglages Système › Confidentialité et sécurité › Réseau local.

Dossiers partagés

Comment accéder au dossier partagé depuis un espace de travail ?

Espaces de travail macOS (macOS 13 ou ultérieur) : les dossiers partagés se montent automatiquement — ouvrez le Finder et cherchez sous /Volumes/My Shared Files. Aucune commande nécessaire.

Espaces de travail Linux : chaque dossier partagé a sa propre commande de montage, affichée directement dans l'application sous l'onglet Fichiers partagés de l'espace de travail. Elle ressemble à ceci, en utilisant le tag propre de ce dossier :

mkdir -p /mnt/my_folder
sudo mount -t virtiofs <folder-tag-shown-in-app> /mnt/my_folder

Utilisez exactement le tag affiché dans l'application — il est unique par dossier, donc copier une commande venant d'ailleurs ne fonctionnera pas.

Presse-papiers & saisie

Le copier-coller ne fonctionne pas entre mon Mac et un espace de travail Linux

Le partage du presse-papiers sous Linux dépend d'un agent exécuté dans l'invité. Suivez ces étapes dans l'ordre :

  1. Dans l'onglet Ressources de l'espace de travail, vérifiez que Partage du presse-papiers est activé.
  2. Dans l'invité, assurez-vous que spice-vdagent est installé : 
    sudo apt install spice-vdagent
  3. Vérifiez que l'agent est bien en cours d'exécution : 
    systemctl status spice-vdagentd
    S'il est inactif, démarrez-le avec sudo systemctl start spice-vdagentd, et si vous êtes sur un bureau graphique, déconnectez-vous et reconnectez-vous pour que la session de bureau le prenne en compte.
  4. Certains environnements de bureau minimaux ou headless ne lancent pas automatiquement spice-vdagent — vérifiez les paramètres de démarrage automatique de votre environnement de bureau si cela ne fonctionne toujours pas une fois l'agent installé et en cours d'exécution.

Le partage du presse-papiers fonctionne actuellement uniquement pour les espaces de travail Linux.

Rosetta (x86_64 sur Apple Silicon)Pro

Comment activer Rosetta dans un espace de travail Debian ?

Debian utilise les mêmes outils apt et update-binfmts qu'Ubuntu. Activez Rosetta pour l'espace de travail dans son onglet Ressources, démarrez l'espace de travail, puis exécutez ceci une fois dans l'invité :

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo apt-get update
sudo apt-get install -y binfmt-support

sudo /usr/sbin/update-binfmts --install rosetta /media/rosetta/rosetta \
  --magic "\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00" \
  --mask "\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff" \
  --credentials yes --preserve yes --fix-binary yes
Comment activer Rosetta dans un espace de travail Fedora ?

Fedora n'embarque pas l'outil update-binfmts de Debian, mais il embarque systemd-binfmt, qui lit exactement le même enregistrement noyau binfmt_misc depuis un fichier de configuration. Activez Rosetta pour l'espace de travail dans son onglet Ressources, démarrez l'espace de travail, puis exécutez ceci une fois dans l'invité :

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo mkdir -p /etc/binfmt.d
sudo tee /etc/binfmt.d/rosetta.conf > /dev/null <<'EOF'
:rosetta:M::\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00:\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff:/media/rosetta/rosetta:CF
EOF

sudo systemctl restart systemd-binfmt

Le fichier rosetta.conf persiste après redémarrage, il s'agit donc d'une configuration unique par espace de travail.

Pont IAPro

Comment connecter Pont IA à Ollama ou MLX ?
  1. Installez et exécutez Ollama ou MLX sur votre Mac, en dehors de l'espace de travail.
  2. Activez Pont IA pour l'espace de travail (activé par défaut dans le profil Bac à sable IA, ou activez-le vous-même dans les paramètres Intégrations ou Ressources de l'espace de travail).
  3. Démarrez l'espace de travail, puis ouvrez son onglet Pont IA — il affiche l'adresse du point de terminaison local et, pour un invité Linux, les commandes exactes pour transférer la connexion.
  4. Dans l'espace de travail, pointez vos outils vers cette adresse exactement comme vous le feriez pour n'importe quel serveur local qui parle le format d'API chat-completions standard.

Diagnostic

Comment exporter les journaux pour résoudre un problème ?

Ouvrez Diagnostic dans la barre latérale, puis cliquez sur Exporter. Cela regroupe vos journaux d'application locaux et vos informations système dans un seul fichier sur votre Mac — pratique à joindre à un e-mail lorsque vous résolvez un problème avec nous.

Rien n'est jamais collecté automatiquement. Cet export ne se produit que lorsque vous l'exécutez vous-même, et le fichier résultant reste sur votre Mac à moins que vous ne choisissiez de l'envoyer.

Espaces de travail jetables & images de base

Que devient un espace de travail jetable quand je le ferme ?

Il est supprimé automatiquement dès que vous le fermez, disque compris. Il n'y a rien à récupérer ensuite — n'utilisez pas un espace de travail jetable pour quoi que ce soit que vous devez conserver.

Comment transformer un espace de travail en image de base réutilisable ?Pro

Arrêtez l'espace de travail, puis choisissez Enregistrer comme image de base depuis le bandeau d'un espace de travail arrêté. Enregistrer à nouveau le même espace de travail plus tard crée une nouvelle image de base distincte, sans remplacer l'ancienne. Gérez et supprimez vos images de base dans Réglages › Images › Images de base.

Où sont stockés mes espaces de travail et mes images, et comment libérer de l'espace ?

Les disques des espaces de travail et les images de base se trouvent sous ~/Library/Application Support/VeloWorkspaces sur votre Mac. Pour libérer de l'espace, supprimez de la bibliothèque les espaces de travail inutiles, et dans Réglages › Images les images téléchargées ou images de base que vous n'utilisez plus.

Général

Velo Workspaces prend-il en charge les invités Windows ?

Pas dans cette version. Velo Workspaces prend actuellement en charge les invités Linux et macOS.

Pourquoi ne puis-je pas modifier certains paramètres pendant qu'un espace de travail est en cours d'exécution ?

Le CPU, la mémoire, le stockage, les dossiers partagés et quelques autres paramètres font partie de la configuration de la machine virtuelle et ne peuvent pas être modifiés pendant son exécution (le framework Virtualization d'Apple ne prend pas en charge leur modification à chaud). Arrêtez l'espace de travail, effectuez le changement, puis redémarrez-le.

Pourquoi ne puis-je pas créer un invité macOS ?

Les invités macOS nécessitent un Mac Apple Silicon comme hôte. Sur un Mac Intel, les invités Linux restent entièrement pris en charge.

Un workspace cloné à partir d'une image de base Ubuntu Server (minimisée) n'obtient pas d'adresse IP

Velo Workspaces attribue une nouvelle adresse MAC unique à chaque workspace, y compris ceux clonés à partir d'une image de base. L'installation minimisée d'Ubuntu Server configure le réseau avec Netplan au-dessus de systemd-networkd, qui lie par défaut l'interface à l'adresse MAC d'origine de l'image de base plutôt que de la faire correspondre par nom d'interface — dès que le clone a une adresse MAC différente, plus rien ne correspond et DHCP n'est jamais sollicité.

Trouvez l'adresse MAC réelle du workspace, puis mettez-la à jour dans la configuration de Netplan :

ip addr show

Notez l'adresse affichée après link/ether pour l'interface (généralement enp0s1), définissez-la comme adresse MAC de cette interface dans la configuration Netplan, puis réappliquez :

sudo sed -i 's/macaddress:.*/macaddress: <new-mac-address>/' /etc/netplan/*.yaml
sudo netplan apply
