Disposable VM vs. Snapshot: What's the Difference?

The short answer: a snapshot keeps state on purpose, and a disposable environment throws it away on purpose. This is the concrete version: what Velo Workspaces' restore points copy on disk, and what "disposable" does instead.

By Gaoliang Luo · Published September 22, 2026 · Updated September 28, 2026

What a restore point copies

A restore point is a real copy. Creating one copies the workspace's main disk, and its saved VM state if the workspace was suspended rather than shut down, into a snapshot folder. Restoring reverses that, putting the disk (and saved state, if there is one) back exactly as it was. Restoring is safe to get wrong, too: the app backs up the workspace's current disk and state before overwriting anything, and puts that backup back automatically if the restore fails partway.

Creating restore points is part of Pro. Restoring ones you already have is free, and stays free if a subscription lapses.

What a disposable workspace does instead

Nothing is copied or kept; that's the point. Closing a disposable workspace deletes it outright, disk and all. No snapshot is involved, because a disposable workspace was never meant to be returned to. The next one doesn't restore from the one you just closed; it clones fresh from a base image, a separate saved template that was never part of the workspace you threw away (see base images as versioned infrastructure).

When to reach for each

A restore point is for a working session you want to be able to rewind. Take one before something risky, a migration or a config change you're unsure of, and if it goes wrong, restore instead of rebuilding. Disposability is for the opposite goal: guaranteeing nothing from this run reaches the next, which matters most in testing, QA, and anywhere an AI agent's generated code runs. The disposability post covers why.

Not either-or

They answer different questions, and one Mac's workspaces can use both. A long-lived project workspace might use restore points as checkpoints during a risky refactor, while a separate disposable workspace handles the next test run with no snapshot at all. What decides it is whether you'll want to go back to that workspace, not which pattern is "better".
