Running Arch Linux on Apple Silicon: What's Different

Fourth in the series on specific distributions, and the odd one out. Ubuntu, Debian and Fedora each ship an official arm64 build from the same project as the x86 one. Arch doesn't, and that changes almost everything else here.

There's no official arm64 Arch

Arch Linux itself targets x86_64 only. What runs on aarch64, Apple silicon included, is Arch Linux ARM (archlinuxarm.org), a separate community project with its own maintainers and its own build infrastructure. It's active and well regarded, but it isn't the Arch project shipping an arm64 version of its own release the way Ubuntu, Debian and Fedora do. In practice, "Arch on Apple silicon" means Arch Linux ARM.

Not in Velo Workspaces' catalog, and not an ISO

Arch is the one distribution in this series that Velo Workspaces doesn't download for you, and the one that needs the most assembly. Arch Linux ARM's download for generic 64-bit ARM machines, the Generic AArch64 build, is a root filesystem tarball rather than a bootable installer, so you can't point a new workspace at it directly. The same downloads page lists images for the Raspberry Pi and other boards; those carry board-specific kernels and boot loaders and won't start in a virtual machine at all.

The practical route is a community-built UEFI installer ISO for aarch64. Archboot is the best known. Create the workspace with Installer image › Choose File…, boot it, and install the way you would on any Arch system. These are unofficial builds, so check the project's own page for the current image and instructions.

Rolling release: no version to pick, one rule to follow

Arch has no release numbers, just a continuously updated package set. The rule that comes with it is on Arch's own wiki: partial upgrades, where you update one package without syncing the whole system, are unsupported and a common source of breakage. Run pacman -Syu, not pacman -Sy followed by a single package.

Nothing is configured for you, starting with networking

A minimal Arch install has no network management enabled: no NetworkManager, no systemd-networkd. That's deliberate. Fedora surprises people with something switched on (SELinux); Arch surprises them with everything off, including the network you need to do anything else. For a VM, systemd-networkd is all you need, since there's no Wi-Fi, just one virtio network interface that wants a DHCP lease:

sudo tee /etc/systemd/network/20-wired.network > /dev/null <<'EOF'
[Match]
Name=en*

[Network]
DHCP=yes
EOF
sudo systemctl enable --now systemd-networkd systemd-resolved

After the install

Install and enable openssh, then type your username in the workspace's Access tab. Sign in to the built-in terminal (Pro) once with your password and click Install Key, and it stops asking for it. When the system is how you want it, save it as a base image so you never repeat the setup.

When Arch makes sense

Pick Arch when you want the newest packages and kernel with no release cadence in the way, and you're comfortable building up a minimal system yourself. That takes time: every setting in the guest OS performance tuning post is yours to make. If you'd rather have a distribution's own tested arm64 build, or a system that's ready in a minute, Ubuntu, Debian, Fedora and Rocky Linux all come as cloud images in Velo Workspaces.
