Start with what's running under you

Everything else builds on one mechanism. Apple Silicon Virtual Machines, Explained covers what the Virtualization framework is, and how it works goes device by device. If you're weighing virtualization against the alternatives, VM vs. container vs. sandbox on macOS and Virtualization.framework vs. QEMU cover the isolation and emulation trade-offs. ARM64 vs. x86-64 and why ARM VMs feel native cover the architecture underneath.

Get Linux running, and know its gotchas

Since Velo Workspaces 1.2, the fastest start is an official cloud image: Ubuntu, Debian, Fedora or Rocky Linux, ready to sign in to about a minute after it downloads. What's new in 1.2 walks through it. Each distribution has its own post with what's different about it: Ubuntu, Debian, Fedora, Rocky Linux, Arch, Kali and NixOS, plus which one fits your work, Server or Desktop, and how VM networking works. For something other than Linux, see macOS guests.

When arm64 isn't enough

x86 software doesn't vanish on Apple silicon. Rosetta 2 in Linux VMs translates individual binaries, can you install x86 Linux at all answers the whole-OS question, and running x86 Docker images covers containers. If something won't run and you don't know why, the triage guide sorts it out.

Running AI agents and local models, safely

This is the deepest part of the blog, best read in roughly this order: how AI coding agents use your computer, what they can access, the Git-specific risk, and what goes wrong unsandboxed, with dated incidents rather than hypotheticals. Then the complete guide to running agents in an isolated VM ties it together, backed by the AI Bridge architecture and what leaves your Mac and what doesn't. On the model side: tools and formats, how much RAM you need, what quantization does, and local vs. cloud models for agents. To pull it together: a safe local AI agent environment checklist.

A disposable-by-default workflow

The habit this blog argues for: what disposability means, how it differs from a snapshot, and how base images, snapshots and clones relate. Managing the images underneath: versioning base images and tuning the guest before you save one.
