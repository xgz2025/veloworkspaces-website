使い始め方

ワークスペースの作成方法

  1. システムの入手元を選ぶ

    サイドバーでライブラリを選び、右上の「+」をクリックします。約 1 分で使える完成済みのシステムなら「クラウドイメージ」、ディストリビューションのインストーラを実行するなら「インストーライメージ」、ベースイメージや手元のディスクから始めるなら「既存の仮想ディスクから起動する」を選びます。

  2. イメージを選ぶ

    ディストリビューションとバージョンを選びます。イメージは配布元のサーバからイメージライブラリにダウンロードされ、公開されているチェックサムで検証され、次回からは再利用されます。ファイルが手元にある場合は「ファイルを選択…」をクリックします。Ubuntu、Fedora Server、Rocky Linux のインストーラでは「自動インストール」をオンのままにすると、インストールが自動で進みます。

  3. 構成して確認し、作成する

    プロファイル（Code & Build、DevOps Lab、AI Sandbox、Office & Study）を選ぶか、CPU・メモリ・ディスクを自分で設定し、ユーザ名とパスワードを入力します。概要を確認して「ワークスペースを作成」をクリックします。アカウントの作成と、この Mac の SSH 鍵の登録はアプリが行います。

使い捨てワークスペースの使い方Pro

  1. 使い捨てワークスペースを追加

    サイドバーで「使い捨てワークスペース」を選び、右上の「+」をクリックして上記の手順に従います。保存済みのベースイメージを「既存の仮想ディスクから起動する」で使うのが最速で、動作確認済みのシステムが数秒で立ち上がります。

  2. 1つのタスクにのみ使う

    テストを実行する、バグを再現する、リスクのあるコマンドを試す——ワークスペースを完全に使い捨てとして扱います。

  3. 閉じる

    使い捨てワークスペースを閉じると、ディスクごと自動的に削除されます。その後片付ける必要も、復元する必要もありません——保持しておく必要のあるものには使い捨てワークスペースを使わないでください。

よくある質問

クラウドイメージと自動インストール

クラウドイメージから作成できる Linux は？

Ubuntu 26.04 / 24.04 LTS、Debian 13 / 12、Fedora 44 Cloud Base、Rocky Linux 10 / 9 です。アプリは配布元の公式イメージをダウンロードし、Apple の Virtualization フレームワーク用に変換して、ユーザ名、パスワード、この Mac の SSH 鍵、ホスト名を cloud-init に渡します。初回起動時にシステムが自動で設定を行い、選んだディスクサイズまで拡張されます。ダウンロード後、たいてい約 1 分でログインできます。

自動で進められるインストーラは？

Ubuntu Server / Desktop、Fedora Server / Everything、Rocky Linux（minimal / DVD）です。「イメージ」の手順で「自動インストール」をオンのままにすると、アカウントと SSH 鍵、この Mac の言語・キーボード・タイムゾーンをアプリがインストーラに答えます。Ubuntu のインストーラは仮想ディスクを消去する前に一度だけ確認を求めるので、バナーの「インストールを確認」をクリックしてください。インストールが終わると、ワークスペースは新しいシステムで再起動します。

手動でインストールするシステムは？

Debian のインストーラ、Fedora Workstation、Kali Linux、NixOS、Alpine Linux は、PC と同じようにワークスペースの画面で各自のインストーラを実行します。Debian を手間なく使いたい場合は Debian のクラウドイメージを選んでください。Apple シリコン搭載の Mac では、Apple の復元イメージから macOS もインストールできます。

ダウンロード済みの ISO やクラウドイメージは使えますか？

はい。「イメージ」の手順で ファイルを選択… をクリックするか、「設定」›「イメージ」の「読み込む…」を使います。ファイル名が配布元のチェックサム一覧にあれば、アプリは使う前に公式のチェックサムで検証します。ダウンロードや読み込みをしたイメージはすべて「設定」›「イメージ」（サイドバーの「イメージ」からも開けます）に残り、再利用・検証・削除ができます。

SSH とターミナル

ワークスペースでターミナルを開くには？Pro

ワークスペースを起動し、「アクセス」タブで「ターミナルを開く」をクリックします。内蔵ターミナルは、アプリがこの Mac 用に作成してキーチェーンに保管している鍵で SSH ログインします。クラウドイメージや自動インストールで作成したワークスペースは、最初からこの鍵を受け入れます。

自分でインストールしたシステムでは、「アクセス」タブにユーザ名を入力し、一度パスワードでログインしてから「鍵をインストール」をクリックします。以後パスワードは不要です。鍵は「設定」›「アクセス」でコピー、読み込み、書き出しができます。

自分のターミナルや VS Code、別のコンピュータから接続できますか？

はい、無料で使えます。「アクセス」タブには、ワークスペースのアドレスとコピーしてすぐ使える ssh コマンド、VS Code の Remote - SSH 拡張機能用の ~/.ssh/config ブロックが表示されます。

ワークスペースは Mac 内部のプライベートネットワークにあるため、ほかのコンピュータからは Mac を経由して接続します。「システム設定」›「一般」›「共有」で「リモートログイン」をオンにし、「アクセス」タブに表示される ssh -J コマンドを使ってください。

macOS が「ローカルネットワーク上のデバイスの検出」を Velo Workspaces に求めるのはなぜ？

ワークスペースは Mac 内部の小さな仮想ネットワーク（192.168.64.x などのアドレス）にあり、macOS はこれをローカルネットワークとして扱います。SSH の確認とターミナルはこのアドレスに接続するため、macOS が一度だけ確認します。アプリがネットワークを探索・スキャンすることはなく、自分のワークスペースにだけ接続します。

「許可しない」を選んだ場合、「アクセス」タブに「ローカルネットワークへのアクセスなし」と表示されます。「システム設定」›「プライバシーとセキュリティ」›「ローカルネットワーク」でオンに戻してください。

共有フォルダ

ワークスペース内から共有フォルダにアクセスするにはどうすればよいですか？

macOS ワークスペース（macOS 13 以降）：共有フォルダは自動的にマウントされます——Finder を開いて /Volumes/My Shared Filesの下を確認してください。コマンドは不要です。

Linux ワークスペース：各共有フォルダには専用のマウントコマンドがあり、アプリ内のワークスペースの「共有ファイル」タブに直接表示されます。そのフォルダ自身のタグを使って、次のような形になります：

mkdir -p /mnt/my_folder
sudo mount -t virtiofs <folder-tag-shown-in-app> /mnt/my_folder

アプリに表示されている通りのタグを使ってください——フォルダごとに固有なので、他から持ってきたコマンドをコピーしても動作しません。

クリップボードと入力

Mac と Linux ワークスペースの間でコピー & ペーストができません

Linux でのクリップボード共有は、ゲスト内で動作するエージェントに依存します。次の手順を順番に確認してください：

  1. ワークスペースの「リソース」タブで、 クリップボード共有 がオンになっていることを確認します。
  2. ゲスト内で、 spice-vdagent がインストールされていることを確認します： 
    sudo apt install spice-vdagent
  3. エージェントが実際に動作しているか確認します： 
    systemctl status spice-vdagentd
    非アクティブな場合は、 sudo systemctl start spice-vdagentdで起動し、グラフィカルデスクトップを使用している場合はログアウトして再度ログインし、デスクトップセッションに反映させてください。
  4. 一部の最小構成またはヘッドレスなデスクトップ環境では、 spice-vdagent が自動的に起動しません——エージェントがインストールされ動作しているのにまだうまくいかない場合は、デスクトップ環境の自動起動設定を確認してください。

クリップボード共有は現在 Linux ワークスペースでのみ動作します。

Rosetta（Apple シリコン上での x86_64）Pro

Debian ワークスペースで Rosetta を有効にするには？

Debian は Ubuntu と同じ apt と update-binfmts ツールを使用します。ワークスペースの「リソース」タブで Rosetta をオンにし、ワークスペースを起動してから、ゲスト内で一度だけ次を実行してください：

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo apt-get update
sudo apt-get install -y binfmt-support

sudo /usr/sbin/update-binfmts --install rosetta /media/rosetta/rosetta \
  --magic "\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00" \
  --mask "\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff" \
  --credentials yes --preserve yes --fix-binary yes
Fedora ワークスペースで Rosetta を有効にするには？

Fedora には Debian の update-binfmts ツールは含まれていませんが、 systemd-binfmtは含まれており、設定ファイルから、まったく同じカーネルの binfmt_misc 登録を読み込みます。ワークスペースの「リソース」タブで Rosetta をオンにし、ワークスペースを起動してから、ゲスト内で一度だけ次を実行してください：

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo mkdir -p /etc/binfmt.d
sudo tee /etc/binfmt.d/rosetta.conf > /dev/null <<'EOF'
:rosetta:M::\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00:\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff:/media/rosetta/rosetta:CF
EOF

sudo systemctl restart systemd-binfmt

rosetta.conf ファイルは再起動後も保持されるため、この設定はワークスペースごとに一度だけ行えば済みます。

AI ブリッジPro

AI ブリッジを Ollama または MLX に接続するには？
  1. ワークスペースの外、あなたの Mac 上で Ollama または MLX をインストールして実行します。
  2. ワークスペースで AI ブリッジを有効にします（AI サンドボックスプロファイルではデフォルトでオン、または自分でワークスペースの「統合」または「リソース」設定でオンにします）。
  3. ワークスペースを起動し、その AI ブリッジタブを開きます——ローカルエンドポイントのアドレスと、Linux ゲストの場合は接続を転送するための正確なコマンドが表示されます。
  4. ワークスペース内で、標準的な chat-completions API 形式を話すローカルサーバーに接続するのと同じように、ツールをそのアドレスに向けてください。

診断

問題解決のためにログをエクスポートするには？

サイドバーから「診断」を開き、「エクスポート」をクリックします。これにより、ローカルのアプリログとシステム情報が Mac 上の1つのファイルにまとめられます——当社とのトラブルシューティングでメールに添付する際に便利です。

何かが自動的に収集されることは一切ありません。このエクスポートはあなたが自分で実行したときにのみ行われ、生成されたファイルは、あなたが送信を選択しない限り Mac 上にとどまります。

使い捨てワークスペース & ベースイメージ

使い捨てワークスペースを閉じるとどうなりますか？

閉じた瞬間に、ディスクごと自動的に削除されます。その後復元する方法はありません——保持しておく必要のあるものには使い捨てワークスペースを使わないでください。

ワークスペースを再利用可能なベースイメージにするにはどうすればよいですか？Pro

ワークスペースを停止し、停止したワークスペースに表示されるバナーから ベースイメージとして保存 を選択します。同じワークスペースを後でもう一度保存すると、以前のものは残したまま新しい独立したベースイメージが作成されます。ベースイメージの管理と削除は「設定」›「イメージ」›「ベースイメージ」で行えます。

ワークスペースとイメージの保存場所は？空き容量を増やすには？

ワークスペースのディスクとベースイメージは、Mac 上の ~/Library/Application Support/VeloWorkspaces に保存されています。空き容量を増やすには、不要なワークスペースをライブラリから削除し、使わなくなったダウンロード済みイメージやベースイメージを「設定」›「イメージ」から削除してください。

一般

Velo Workspaces は Windows ゲストに対応していますか？

このリリースでは未対応です。Velo Workspaces は現在 Linux と macOS ゲストに対応しています。

ワークスペースの実行中に一部の設定を変更できないのはなぜですか？

CPU、メモリ、ストレージ、共有フォルダ、その他いくつかの設定は仮想マシンの構成の一部であり、実行中は変更できません（Apple の Virtualization フレームワークはこれらのホットプラグに対応していません）。ワークスペースを停止し、変更を行ってから、再度起動してください。

macOS ゲストを作成できないのはなぜですか？

macOS ゲストにはホストとして Apple シリコン搭載 Mac が必要です。Intel Mac では、Linux ゲストは引き続き完全にサポートされています。

Ubuntu Server（最小構成）のベースイメージから複製したワークスペースが IP アドレスを取得できない

Velo Workspaces は、ベースイメージから複製したものも含め、ワークスペースごとに新しい一意の MAC アドレスを割り当てます。Ubuntu Server の最小構成インストールは systemd-networkd 上で Netplan を使ってネットワークを設定しますが、デフォルトではインターフェース名ではなく、ベースイメージの元の MAC アドレスにインターフェースを紐付けます。そのため複製後に MAC アドレスが変わると、設定が一致しなくなり DHCP が要求されなくなります。

ワークスペースの実際の MAC アドレスを確認し、netplan の設定に反映します。

ip addr show

該当インターフェース（通常は enp0s1）の link/ether の後に表示されるアドレスを控え、それを netplan 設定内のそのインターフェースの MAC アドレスとして設定して、再適用します。

sudo sed -i 's/macaddress:.*/macaddress: <new-mac-address>/' /etc/netplan/*.yaml
sudo netplan apply
