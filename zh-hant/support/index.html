入門指南

如何建立工作區

  1. 選擇系統來源

    在側邊欄選擇一個資料庫，然後點擊右上角的「+」。想要約一分鐘就能用的現成系統，選「雲端映像」；想執行發行版本身的安裝程式，選「安裝映像」；想從基礎映像或現有磁碟開始，選「從現有的虛擬磁碟開機」。

  2. 選擇映像

    選擇發行版與版本。映像會從發行方自己的伺服器下載到你的映像資料庫，以官方公布的檢查碼驗證，下次直接重複使用。已經有檔案了？點擊「選擇檔案…」。Ubuntu、Fedora Server 與 Rocky Linux 的安裝程式只要保持「自動安裝」開啟，安裝就會自行完成。

  3. 設定、確認並建立

    選擇一個預設（Code & Build、DevOps Lab、AI Sandbox 或 Office & Study），或自行設定 CPU、記憶體與磁碟，再輸入使用者名稱與密碼。確認摘要後點擊「建立工作區」。App 會為你建立帳號，並加入這台 Mac 的 SSH 金鑰。

如何使用用後即焚工作區Pro

  1. 新增用後即焚工作區

    在側邊欄選擇「用後即焚工作區」，點擊右上角的「+」，依照上面的步驟操作。最快的方式是用已儲存的基礎映像「從現有的虛擬磁碟開機」：一個已驗證可用的系統，幾秒就能執行。

  2. 僅用於一項任務

    執行你的測試、重現錯誤，或嘗試有風險的指令——把這個工作區當作完全可以捨棄的對象。

  3. 關閉它

    關閉用後即焚工作區會自動將其刪除，包括磁碟在內。之後無需清理，也無法復原——不要把用後即焚工作區用於任何你需要保留的東西。

常見問題

雲端映像與自動安裝

哪些 Linux 可以用雲端映像建立？

Ubuntu 26.04 與 24.04 LTS、Debian 13 與 12、Fedora 44 Cloud Base，以及 Rocky Linux 10 與 9。App 會下載發行方的官方映像，轉換成 Apple Virtualization 框架可用的格式，並把使用者名稱、密碼、這台 Mac 的 SSH 金鑰與主機名稱交給 cloud-init。首次開機時系統會自行完成設定，並擴展到你選擇的磁碟大小。下載完成後，通常約一分鐘就能登入。

哪些安裝程式可以自動完成？

Ubuntu Server 與 Desktop、Fedora Server 與 Everything，以及 Rocky Linux（minimal 與 DVD）。在「映像」步驟保持「自動安裝」開啟，App 會替你回答安裝程式的問題：你的帳號與 SSH 金鑰，以及這台 Mac 的語言、鍵盤與時區。安裝程式不會中途提問，清除虛擬磁碟前也不會要求確認。安裝完成後，工作區會重新開機進入新系統。

哪些系統需要手動安裝？

Debian 安裝程式、Fedora Workstation、Kali Linux、NixOS 與 Alpine Linux 會在工作區的顯示畫面中執行各自的安裝程式，和在 PC 上一樣。想要免手動的 Debian，請改用 Debian 雲端映像。在搭載 Apple 晶片的 Mac 上，也可以用 Apple 的回復映像安裝 macOS。

為什麼手動安裝的工作區會詢問「客體作業系統安裝完成了嗎？」

這是手動安裝（例如 Kali Linux、NixOS、Alpine Linux 或 Debian 安裝程式）之後的正常行為。自動安裝何時完成，Velo Workspaces 能自行判斷；手動安裝何時完成，只有你知道。安裝系統期間，工作區使用「大字體」顯示縮放，讓開機選單與安裝程式清楚易讀。安裝好的系統開機後，點擊「安裝已完成」：之後不再掛載安裝媒體，並自下次啟動起使用工作區自己的顯示設定。若要切換，請將工作區停止後再啟動一次；在客體系統內部重新開機並不足夠。

可以用已經下載好的 ISO 或雲端映像嗎？

可以。在「映像」步驟點擊 選擇檔案… ，或在「設定 › 映像」中點擊「匯入⋯」。如果檔名出現在發行方的檢查碼清單中，App 會在使用前以官方檢查碼驗證。下載或匯入的映像都會保留在「設定 › 映像」中（側邊欄的「映像」也能開啟），可以重複使用、驗證或刪除。

SSH 與終端機

如何在工作區中開啟終端機？Pro

啟動工作區，打開它的「存取」標籤頁，點擊「打開終端機」。內建終端機會用 App 為這台 Mac 產生並保存在鑰匙圈中的金鑰透過 SSH 登入。用雲端映像或自動安裝建立的工作區已經信任這把金鑰。

如果是你自己安裝的系統，請在「存取」標籤頁輸入使用者名稱，用密碼登入一次，再點擊「安裝金鑰」，之後就不再需要密碼。你可以在「設定 › 存取」中拷貝、匯入或匯出金鑰。

可以用自己的終端機或 VS Code，或從另一台電腦連線嗎？

可以，而且免費。「存取」標籤頁會顯示工作區的位址和可直接拷貝的 ssh 指令，以及供 VS Code Remote - SSH 延伸功能使用的 ~/.ssh/config 設定區塊。它們使用的是你自己的 SSH 金鑰，而不是內建終端機保存在鑰匙圈中的那把。建立工作區時，請在「SSH 公開金鑰」中貼上你的公開金鑰，或開啟「允許使用密碼進行 SSH 登入」。

工作區位於 Mac 內部的私有網路中，其他電腦需要經由你的 Mac 連線。在「系統設定 › 一般 › 共享」中開啟「遠端登入」，然後使用「存取」標籤頁中顯示的 ssh -J 指令。

為什麼 macOS 詢問是否允許 Velo Workspaces 尋找區域網路上的裝置？

工作區位於 Mac 內部的一個小型虛擬網路中（位址類似 192.168.64.x），macOS 把它視為區域網路。SSH 檢查與終端機會連線到這個位址，所以 macOS 會詢問一次。App 從不瀏覽或掃描你的網路，只連線到它自己的工作區。

如果你選了「不允許」，「存取」標籤頁會顯示「無本機網路取用權限」。請在「系統設定 › 隱私權與安全性 › 本機網路」中重新開啟。

共用資料夾

如何從工作區內部存取共用資料夾？

macOS 工作區（macOS 13 或更新版本）：共用資料夾會自動掛載——開啟 Finder，查看 /Volumes/My Shared Files路徑下的內容。無需任何指令。

Linux 工作區：每個共用資料夾都有自己的掛載指令，會直接顯示在應用程式內該工作區的「共用檔案」分頁中，使用該資料夾專屬的標籤，形如：

mkdir -p /mnt/my_folder
sudo mount -t virtiofs <folder-tag-shown-in-app> /mnt/my_folder

請使用應用程式中顯示的確切標籤——每個資料夾的標籤都是唯一的，因此從別處複製的指令不會生效。

剪貼簿與輸入

Mac 與 Linux 工作區之間的複製貼上不生效

Linux 上的剪貼簿共用依賴於虛擬機器內執行的代理程式。請依序檢查以下幾點：

  1. 在工作區的「資源」分頁中，確認 剪貼簿共用 已開啟。
  2. 在虛擬機器內，確認 spice-vdagent 已安裝： 
    sudo apt install spice-vdagent
  3. 確認該代理程式確實正在執行： 
    systemctl status spice-vdagentd
    如果處於未啟用狀態，用 sudo systemctl start spice-vdagentd啟動它；如果你使用的是圖形化桌面環境，請登出後重新登入，讓桌面工作階段辨識它。
  4. 某些精簡版或無圖形介面的桌面環境不會自動啟動 spice-vdagent ——如果代理程式已安裝並執行，但仍然不生效，請檢查你桌面環境的自動啟動設定。

剪貼簿共用目前僅適用於 Linux 工作區。

Rosetta（在 Apple 晶片上執行 x86_64）Pro

如何在 Debian 工作區中啟用 Rosetta？

Debian 使用與 Ubuntu 相同的 apt 與 update-binfmts 工具。在工作區的「資源」分頁中開啟 Rosetta，啟動該工作區，然後在虛擬機器內執行一次以下指令：

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo apt-get update
sudo apt-get install -y binfmt-support

sudo /usr/sbin/update-binfmts --install rosetta /media/rosetta/rosetta \
  --magic "\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00" \
  --mask "\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff" \
  --credentials yes --preserve yes --fix-binary yes
如何在 Fedora 工作區中啟用 Rosetta？

Fedora 沒有內建 Debian 的 update-binfmts 工具，但內建了 systemd-binfmt，它會從設定檔中讀取與前者完全相同的核心 binfmt_misc 註冊資訊。在工作區的「資源」分頁中開啟 Rosetta，啟動該工作區，然後在虛擬機器內執行一次以下指令：

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo mkdir -p /etc/binfmt.d
sudo tee /etc/binfmt.d/rosetta.conf > /dev/null <<'EOF'
:rosetta:M::\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00:\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff:/media/rosetta/rosetta:CF
EOF

sudo systemctl restart systemd-binfmt

rosetta.conf 檔案會在重新啟動後依然保留，因此每個工作區只需設定一次。

AI 橋接Pro

如何將 AI 橋接連接到 Ollama 或 MLX？
  1. 在工作區之外，於你的 Mac 上安裝並執行 Ollama 或 MLX。
  2. 為該工作區啟用 AI 橋接（在 AI 沙盒預設中預設為開啟，也可以自行在工作區的「整合」或「資源」設定中開啟）。
  3. 啟動工作區，然後開啟其 AI 橋接分頁——其中會顯示本機端點位址，對於 Linux 虛擬機器，還會顯示轉發連線所需的確切指令。
  4. 在工作區內，把你的工具指向這個位址，就像連接任何使用標準 chat-completions API 格式的本機伺服器一樣。

診斷

如何匯出紀錄以排解問題？

從側邊欄開啟「診斷」，然後點擊「匯出」。這會將本機應用程式紀錄和系統資訊打包成 Mac 上的一個檔案——便於在與我們排解問題時附加到郵件中。

系統絕不會自動收集任何內容。該匯出操作只有在你自己執行時才會發生，產生的檔案會保留在你的 Mac 上，除非你選擇傳送它。

用後即焚工作區與基礎映像檔

關閉用後即焚工作區後會發生什麼事？

關閉的瞬間它會被自動刪除，包括其磁碟。之後無法復原——不要把用後即焚工作區用於任何你需要保留的東西。

如何把一個工作區變成可重複使用的基礎映像檔？Pro

停止該工作區，然後在已停止工作區顯示的橫幅中選擇 儲存為基礎映像檔 。之後再次儲存同一個工作區，會建立一個新的獨立基礎映像，舊的仍會保留。可以在「設定 › 映像 › 基礎映像」中管理與刪除基礎映像。

工作區與映像存放在哪裡？如何釋放空間？

工作區磁碟與基礎映像檔存放在你 Mac 上的 ~/Library/Application Support/VeloWorkspaces 目錄下。要釋放空間，請從資料庫刪除不再需要的工作區，並在「設定 › 映像」中刪除不再使用的已下載映像或基礎映像。

一般問題

Velo Workspaces 支援 Windows 虛擬機器嗎？

此版本尚不支援。Velo Workspaces 目前支援 Linux 與 macOS 虛擬機器。

為什麼工作區執行時無法變更某些設定？

CPU、記憶體、儲存空間、共用資料夾等一些設定屬於虛擬機器設定的一部分，執行期間無法變更（Apple 的 Virtualization 框架不支援對這些項目進行熱插拔）。請先停止該工作區，完成變更後再重新啟動。

為什麼我無法建立 macOS 虛擬機器？

建立 macOS 虛擬機器需要以 Apple 晶片 Mac 作為主機。在 Intel Mac 上，Linux 虛擬機器仍然完全受支援。

從 Ubuntu Server（最小化安裝）基礎映像複製的工作區無法取得 IP 位址

Velo Workspaces 會為每個工作區指派一個新的唯一 MAC 位址，包括從基礎映像複製出的工作區。Ubuntu Server 的最小化安裝預設會在 systemd-networkd 之上使用 Netplan 設定網路，它預設會將網路介面綁定到基礎映像原本的 MAC 位址，而不是依介面名稱比對——因此一旦複製後的 MAC 位址不同，設定就不再相符，也就永遠不會發出 DHCP 請求。

找出工作區實際的 MAC 位址，然後更新到 netplan 的設定檔中：

ip addr show

記下該網路介面（通常是 enp0s1）link/ether 後顯示的位址，將其設為 netplan 設定中該介面的 MAC 位址，然後重新套用：

sudo sed -i 's/macaddress:.*/macaddress: <new-mac-address>/' /etc/netplan/*.yaml
sudo netplan apply
