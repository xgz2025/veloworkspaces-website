시작하기

워크스페이스 생성 방법

  1. 시스템을 가져올 곳 고르기

    사이드바에서 라이브러리를 고른 다음 오른쪽 위의 “+”를 클릭합니다. 1분 정도면 준비되는 완성형 시스템은 “클라우드 이미지”, 배포판 설치 프로그램을 실행하려면 “설치 이미지”, 기본 이미지나 가지고 있는 디스크로 시작하려면 “기존 가상 디스크에서 부팅하기”를 선택하세요.

  2. 이미지 고르기

    배포판과 버전을 고릅니다. 이미지는 배포처 서버에서 이미지 라이브러리로 내려받아지고, 공개된 체크섬으로 검증되며, 다음에는 다시 사용됩니다. 파일이 이미 있다면 “파일 선택…”을 클릭하세요. Ubuntu, Fedora Server, Rocky Linux 설치 프로그램은 “자동 설치”를 켜 두면 설치가 알아서 진행됩니다.

  3. 구성하고 검토한 뒤 만들기

    프로필(Code & Build, DevOps Lab, AI Sandbox, Office & Study)을 고르거나 CPU·메모리·디스크를 직접 정하고, 사용자 이름과 암호를 입력합니다. 요약을 확인하고 “작업 공간 만들기”를 클릭하세요. 계정 생성과 이 Mac의 SSH 키 등록은 앱이 해 줍니다.

일회용 워크스페이스 사용법Pro

  1. 일회용 워크스페이스 추가

    사이드바에서 “일회용 작업 공간”을 선택하고 오른쪽 위의 “+”를 클릭한 뒤 위 단계를 따르세요. 저장해 둔 기본 이미지로 “기존 가상 디스크에서 부팅하기”를 고르면 가장 빠릅니다. 검증된 시스템이 몇 초 만에 켜집니다.

  2. 정확히 하나의 작업에만 사용

    테스트를 실행하거나, 버그를 재현하거나, 위험한 명령을 시도해 보세요 — 워크스페이스를 완전히 소모품으로 취급하세요.

  3. 닫기

    일회용 워크스페이스를 닫으면 디스크를 포함해 자동으로 삭제됩니다. 이후 정리할 것도, 복구할 것도 없습니다 — 보관해야 하는 것에는 일회용 워크스페이스를 사용하지 마세요.

자주 묻는 질문

클라우드 이미지와 자동 설치

클라우드 이미지로 만들 수 있는 Linux는 무엇인가요?

Ubuntu 26.04·24.04 LTS, Debian 13·12, Fedora 44 Cloud Base, Rocky Linux 10·9입니다. 앱이 배포처의 공식 이미지를 내려받아 Apple Virtualization 프레임워크용으로 변환하고, 사용자 이름, 암호, 이 Mac의 SSH 키, 호스트 이름을 cloud-init에 넘깁니다. 처음 부팅할 때 시스템이 스스로 설정을 마치고 선택한 디스크 크기까지 늘어납니다. 다운로드가 끝나면 보통 1분 정도 뒤 로그인할 수 있습니다.

알아서 진행되는 설치 프로그램은 무엇인가요?

Ubuntu Server·Desktop, Fedora Server·Everything, Rocky Linux(minimal·DVD)입니다. “이미지” 단계에서 “자동 설치”를 켜 두면 계정과 SSH 키, 이 Mac의 언어·키보드·시간대를 앱이 설치 프로그램에 대신 답합니다. Ubuntu 설치 프로그램은 가상 디스크를 지우기 전에 한 번 확인을 요청하므로 배너의 “설치 확인”을 클릭하세요. 설치가 끝나면 작업 공간이 새 시스템으로 다시 시작됩니다.

직접 설치해야 하는 시스템은 무엇인가요?

Debian 설치 프로그램, Fedora Workstation, Kali Linux, NixOS, Alpine Linux는 PC에서처럼 작업 공간 화면에서 각자의 설치 프로그램을 실행합니다. 손대지 않고 Debian을 쓰려면 Debian 클라우드 이미지를 사용하세요. Apple 실리콘 Mac에서는 Apple 복원 이미지로 macOS도 설치할 수 있습니다.

이미 내려받은 ISO나 클라우드 이미지를 쓸 수 있나요?

네. “이미지” 단계에서 파일 선택… 을 클릭하거나, 설정 › 이미지에서 “가져오기…”를 사용하세요. 파일 이름이 배포처의 체크섬 목록에 있으면 앱이 사용하기 전에 공식 체크섬으로 검증합니다. 내려받거나 가져온 이미지는 모두 설정 › 이미지(사이드바의 “이미지”)에 남아 있어 다시 쓰거나 검증하거나 삭제할 수 있습니다.

SSH와 터미널

작업 공간에서 터미널을 어떻게 여나요?Pro

작업 공간을 시작하고 “접근” 탭에서 “터미널 열기”를 클릭합니다. 내장 터미널은 앱이 이 Mac용으로 만들어 키체인에 보관한 키로 SSH 로그인합니다. 클라우드 이미지나 자동 설치로 만든 작업 공간은 처음부터 이 키를 허용합니다.

직접 설치한 시스템이라면 “접근” 탭에 사용자 이름을 입력하고 암호로 한 번 로그인한 뒤 “키 설치”를 클릭하세요. 그다음부터는 암호가 필요 없습니다. 키는 설정 › 접근에서 복사하거나 가져오거나 내보낼 수 있습니다.

내 터미널이나 VS Code를 쓰거나 다른 컴퓨터에서 접속할 수 있나요?

네, 이 부분은 무료입니다. “접근” 탭에는 작업 공간 주소와 바로 복사할 수 있는 ssh 명령, VS Code Remote - SSH 확장용 ~/.ssh/config 블록이 표시됩니다.

작업 공간은 Mac 내부의 사설 네트워크에 있으므로 다른 컴퓨터는 Mac을 거쳐 접속합니다. 시스템 설정 › 일반 › 공유에서 ‘원격 로그인’을 켠 다음, “접근” 탭에 표시된 ssh -J 명령을 사용하세요.

macOS가 Velo Workspaces에 로컬 네트워크의 기기를 찾도록 허용할지 묻는 이유는 무엇인가요?

작업 공간은 Mac 내부의 작은 가상 네트워크(192.168.64.x 같은 주소)에 있고, macOS는 이를 로컬 네트워크로 봅니다. SSH 확인과 터미널이 그 주소로 연결하므로 macOS가 한 번 묻습니다. 앱은 네트워크를 탐색하거나 스캔하지 않으며, 자신의 작업 공간에만 연결합니다.

“허용 안 함”을 선택했다면 “접근” 탭에 “로컬 네트워크 접근 없음”이 표시됩니다. 시스템 설정 › 개인정보 보호 및 보안 › 로컬 네트워크에서 다시 켜세요.

공유 폴더

워크스페이스 내부에서 공유 폴더에 접근하려면 어떻게 하나요?

macOS 워크스페이스(macOS 13 이상): 공유 폴더는 자동으로 마운트됩니다 — Finder를 열고 /Volumes/My Shared Files아래를 확인하세요. 명령어가 필요 없습니다.

Linux 워크스페이스: 각 공유 폴더에는 고유한 마운트 명령어가 있으며, 앱 내 워크스페이스의 공유 파일 탭에 바로 표시됩니다. 해당 폴더 자체의 태그를 사용해 다음과 같은 형태입니다:

mkdir -p /mnt/my_folder
sudo mount -t virtiofs <folder-tag-shown-in-app> /mnt/my_folder

앱에 표시된 태그를 정확히 사용하세요 — 폴더마다 고유하므로 다른 곳에서 복사한 명령어는 작동하지 않습니다.

클립보드 및 입력

Mac과 Linux 워크스페이스 간 복사 및 붙여넣기가 작동하지 않습니다

Linux에서 클립보드 공유는 게스트 내부에서 실행되는 에이전트에 의존합니다. 다음을 순서대로 확인하세요:

  1. 워크스페이스의 리소스 탭에서 클립보드 공유 가 켜져 있는지 확인하세요.
  2. 게스트 내부에서 spice-vdagent 가 설치되어 있는지 확인하세요: 
    sudo apt install spice-vdagent
  3. 에이전트가 실제로 실행 중인지 확인하세요: 
    systemctl status spice-vdagentd
    비활성 상태라면 sudo systemctl start spice-vdagentd로 시작하고, 그래픽 데스크톱을 사용 중이라면 로그아웃 후 다시 로그인해 데스크톱 세션이 이를 인식하도록 하세요.
  4. 일부 최소 구성 또는 헤드리스 데스크톱 환경에서는 spice-vdagent 가 자동으로 실행되지 않습니다 — 에이전트가 설치되어 실행 중인데도 여전히 작동하지 않으면 데스크톱 환경의 자동 시작 설정을 확인하세요.

클립보드 공유는 현재 Linux 워크스페이스에서만 작동합니다.

Rosetta(Apple 실리콘에서의 x86_64)Pro

Debian 워크스페이스에서 Rosetta를 활성화하려면 어떻게 하나요?

Debian은 Ubuntu와 동일한 apt 및 update-binfmts 도구를 사용합니다. 워크스페이스의 리소스 탭에서 Rosetta를 켜고, 워크스페이스를 시작한 뒤, 게스트 내부에서 다음을 한 번 실행하세요:

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo apt-get update
sudo apt-get install -y binfmt-support

sudo /usr/sbin/update-binfmts --install rosetta /media/rosetta/rosetta \
  --magic "\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00" \
  --mask "\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff" \
  --credentials yes --preserve yes --fix-binary yes
Fedora 워크스페이스에서 Rosetta를 활성화하려면 어떻게 하나요?

Fedora에는 Debian의 update-binfmts 도구는 없지만, systemd-binfmt는 있으며, 설정 파일에서 정확히 동일한 커널 binfmt_misc 등록을 읽어들입니다. 워크스페이스의 리소스 탭에서 Rosetta를 켜고, 워크스페이스를 시작한 뒤, 게스트 내부에서 다음을 한 번 실행하세요:

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo mkdir -p /etc/binfmt.d
sudo tee /etc/binfmt.d/rosetta.conf > /dev/null <<'EOF'
:rosetta:M::\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00:\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff:/media/rosetta/rosetta:CF
EOF

sudo systemctl restart systemd-binfmt

rosetta.conf 파일은 재부팅 후에도 유지되므로, 워크스페이스마다 한 번만 설정하면 됩니다.

AI 브리지Pro

AI 브리지를 Ollama 또는 MLX에 연결하려면 어떻게 하나요?
  1. 워크스페이스 밖, 여러분의 Mac에 Ollama 또는 MLX를 설치하고 실행하세요.
  2. 워크스페이스에 AI 브리지를 활성화하세요(AI 샌드박스 프로필에서는 기본적으로 켜져 있으며, 또는 워크스페이스의 통합 또는 리소스 설정에서 직접 켤 수 있습니다).
  3. 워크스페이스를 시작한 뒤 AI 브리지 탭을 여세요 — 로컬 엔드포인트 주소와, Linux 게스트의 경우 연결을 전달하기 위한 정확한 명령어가 표시됩니다.
  4. 워크스페이스 내부에서, 표준 chat-completions API 형식을 사용하는 다른 로컬 서버에 연결할 때와 마찬가지 방식으로 도구를 해당 주소로 연결하세요.

진단

문제 해결을 위해 로그를 내보내려면 어떻게 하나요?

사이드바에서 진단을 열고 내보내기를 클릭하세요. 이렇게 하면 로컬 앱 로그와 시스템 정보가 Mac의 단일 파일로 정리됩니다 — 저희와 문제를 해결할 때 이메일에 첨부하기 편리합니다.

어떤 것도 자동으로 수집되지 않습니다, 절대로. 이 내보내기는 사용자가 직접 실행할 때만 이루어지며, 생성된 파일은 사용자가 보내기로 선택하지 않는 한 Mac에 남아 있습니다.

일회용 워크스페이스 및 베이스 이미지

일회용 워크스페이스를 닫으면 어떻게 되나요?

닫는 순간 디스크를 포함해 자동으로 삭제됩니다. 이후 복구할 방법이 없습니다 — 보관해야 하는 것에는 일회용 워크스페이스를 사용하지 마세요.

워크스페이스를 재사용 가능한 베이스 이미지로 만들려면 어떻게 하나요?Pro

워크스페이스를 중지한 뒤, 중지된 워크스페이스에 표시되는 배너에서 베이스 이미지로 저장 을 선택하세요. 나중에 같은 작업 공간을 다시 저장하면 이전 이미지는 그대로 두고 새롭고 독립적인 기본 이미지가 만들어집니다. 기본 이미지 관리와 삭제는 설정 › 이미지 › 기본 이미지에서 할 수 있습니다.

작업 공간과 이미지는 어디에 저장되며, 공간은 어떻게 확보하나요?

워크스페이스 디스크와 베이스 이미지는 Mac의 ~/Library/Application Support/VeloWorkspaces 에 저장됩니다. 공간을 확보하려면 필요 없는 작업 공간을 라이브러리에서 삭제하고, 쓰지 않는 다운로드 이미지나 기본 이미지를 설정 › 이미지에서 삭제하세요.

일반

Velo Workspaces가 Windows 게스트를 지원하나요?

이번 릴리스에서는 지원하지 않습니다. Velo Workspaces는 현재 Linux와 macOS 게스트를 지원합니다.

워크스페이스가 실행 중일 때 일부 설정을 변경할 수 없는 이유는 무엇인가요?

CPU, 메모리, 스토리지, 공유 폴더 등 몇 가지 설정은 가상 머신 구성의 일부이며 실행 중에는 변경할 수 없습니다(Apple의 Virtualization 프레임워크는 이를 핫플러그로 지원하지 않습니다). 워크스페이스를 중지하고 변경한 뒤 다시 시작하세요.

macOS 게스트를 만들 수 없는 이유는 무엇인가요?

macOS 게스트는 호스트로 Apple 실리콘 Mac이 필요합니다. Intel Mac에서는 Linux 게스트가 여전히 완전히 지원됩니다.

Ubuntu Server(최소 설치) 기본 이미지에서 복제한 워크스페이스가 IP 주소를 받지 못함

Velo Workspaces는 기본 이미지에서 복제한 워크스페이스를 포함해 모든 워크스페이스에 새로운 고유 MAC 주소를 할당합니다. Ubuntu Server의 최소 설치는 systemd-networkd 위에서 Netplan으로 네트워크를 구성하는데, 기본적으로 인터페이스 이름이 아니라 기본 이미지의 원래 MAC 주소로 인터페이스를 고정합니다. 따라서 복제본이 다른 MAC 주소를 갖게 되면 아무것도 일치하지 않아 DHCP 요청이 전혀 이루어지지 않습니다.

워크스페이스의 실제 MAC 주소를 확인한 다음 netplan 설정에 반영하세요:

ip addr show

해당 인터페이스(보통 enp0s1)의 link/ether 뒤에 표시된 주소를 적어두고, 이를 netplan 설정에서 해당 인터페이스의 MAC 주소로 설정한 뒤 다시 적용하세요:

sudo sed -i 's/macaddress:.*/macaddress: <new-mac-address>/' /etc/netplan/*.yaml
sudo netplan apply
