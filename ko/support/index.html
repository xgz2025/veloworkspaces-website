시작하기

워크스페이스 생성 방법

  1. 새 워크스페이스 열기

    워크스페이스 라이브러리에서 새 워크스페이스를 선택하고 이미지 소스를 고르세요: 공식 이미지, 기존 가상 디스크, 또는 저장된 베이스 이미지.

  2. 프로필 선택

    작업에 맞는 프로필을 선택하세요 — 코드 및 빌드, DevOps 랩, AI 샌드박스 등 — 또는 CPU, 메모리, 스토리지를 직접 설정하세요.

  3. 검토 후 실행

    요약을 확인한 뒤 설치를 시작하세요(베이스 이미지 복제의 경우 부팅). 공식 이미지는 처음 사용할 때 해당 프로젝트 자체 소스에서 직접 다운로드됩니다.

일회용 워크스페이스 사용법

  1. 워크스페이스를 일회용으로 표시

    워크스페이스를 생성할 때 일회용 옵션을 켜세요 — 베이스 이미지와 함께 사용하면 즉시 검증된 상태에서 시작할 수 있어 가장 좋습니다.

  2. 정확히 하나의 작업에만 사용

    테스트를 실행하거나, 버그를 재현하거나, 위험한 명령을 시도해 보세요 — 워크스페이스를 완전히 소모품으로 취급하세요.

  3. 닫기

    일회용 워크스페이스를 닫으면 디스크를 포함해 자동으로 삭제됩니다. 이후 정리할 것도, 복구할 것도 없습니다 — 보관해야 하는 것에는 일회용 워크스페이스를 사용하지 마세요.

자주 묻는 질문

공유 폴더

워크스페이스 내부에서 공유 폴더에 접근하려면 어떻게 하나요?

macOS 워크스페이스(macOS 13 이상): 공유 폴더는 자동으로 마운트됩니다 — Finder를 열고 /Volumes/My Shared Files아래를 확인하세요. 명령어가 필요 없습니다.

Linux 워크스페이스: 각 공유 폴더에는 고유한 마운트 명령어가 있으며, 앱 내 워크스페이스의 공유 파일 탭에 바로 표시됩니다. 해당 폴더 자체의 태그를 사용해 다음과 같은 형태입니다:

mkdir -p /mnt/my_folder
sudo mount -t virtiofs <folder-tag-shown-in-app> /mnt/my_folder

앱에 표시된 태그를 정확히 사용하세요 — 폴더마다 고유하므로 다른 곳에서 복사한 명령어는 작동하지 않습니다.

클립보드 및 입력

Mac과 Linux 워크스페이스 간 복사 및 붙여넣기가 작동하지 않습니다

Linux에서 클립보드 공유는 게스트 내부에서 실행되는 에이전트에 의존합니다. 다음을 순서대로 확인하세요:

  1. 워크스페이스의 리소스 탭에서 클립보드 공유 가 켜져 있는지 확인하세요.
  2. 게스트 내부에서 spice-vdagent 가 설치되어 있는지 확인하세요: 
    sudo apt install spice-vdagent
  3. 에이전트가 실제로 실행 중인지 확인하세요: 
    systemctl status spice-vdagentd
    비활성 상태라면 sudo systemctl start spice-vdagentd로 시작하고, 그래픽 데스크톱을 사용 중이라면 로그아웃 후 다시 로그인해 데스크톱 세션이 이를 인식하도록 하세요.
  4. 일부 최소 구성 또는 헤드리스 데스크톱 환경에서는 spice-vdagent 가 자동으로 실행되지 않습니다 — 에이전트가 설치되어 실행 중인데도 여전히 작동하지 않으면 데스크톱 환경의 자동 시작 설정을 확인하세요.

클립보드 공유는 현재 Linux 워크스페이스에서만 작동합니다.

Rosetta(Apple 실리콘에서의 x86_64)

Debian 워크스페이스에서 Rosetta를 활성화하려면 어떻게 하나요?

Debian은 Ubuntu와 동일한 apt 및 update-binfmts 도구를 사용합니다. 워크스페이스의 리소스 탭에서 Rosetta를 켜고, 워크스페이스를 시작한 뒤, 게스트 내부에서 다음을 한 번 실행하세요:

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo apt-get update
sudo apt-get install -y binfmt-support

sudo /usr/sbin/update-binfmts --install rosetta /media/rosetta/rosetta \
  --magic "\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00" \
  --mask "\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff" \
  --credentials yes --preserve yes --fix-binary yes
Fedora 워크스페이스에서 Rosetta를 활성화하려면 어떻게 하나요?

Fedora에는 Debian의 update-binfmts 도구는 없지만, systemd-binfmt는 있으며, 설정 파일에서 정확히 동일한 커널 binfmt_misc 등록을 읽어들입니다. 워크스페이스의 리소스 탭에서 Rosetta를 켜고, 워크스페이스를 시작한 뒤, 게스트 내부에서 다음을 한 번 실행하세요:

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo mkdir -p /etc/binfmt.d
sudo tee /etc/binfmt.d/rosetta.conf > /dev/null <<'EOF'
:rosetta:M::\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00:\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff:/media/rosetta/rosetta:CF
EOF

sudo systemctl restart systemd-binfmt

rosetta.conf 파일은 재부팅 후에도 유지되므로, 워크스페이스마다 한 번만 설정하면 됩니다.

AI 브리지

AI 브리지를 Ollama에 연결하려면 어떻게 하나요?
  1. 워크스페이스 밖, 여러분의 Mac에 Ollama를 설치하고 실행하세요.
  2. 워크스페이스에 AI 브리지를 활성화하세요(AI 샌드박스 프로필에서는 기본적으로 켜져 있으며, 또는 워크스페이스의 통합 또는 리소스 설정에서 직접 켤 수 있습니다).
  3. 워크스페이스를 시작한 뒤 AI 브리지 탭을 여세요 — 로컬 엔드포인트 주소와, Linux 게스트의 경우 연결을 전달하기 위한 정확한 명령어가 표시됩니다.
  4. 워크스페이스 내부에서, 표준 chat-completions API 형식을 사용하는 다른 로컬 서버에 연결할 때와 마찬가지 방식으로 도구를 해당 주소로 연결하세요.

일회용 워크스페이스 및 베이스 이미지

일회용 워크스페이스를 닫으면 어떻게 되나요?

닫는 순간 디스크를 포함해 자동으로 삭제됩니다. 이후 복구할 방법이 없습니다 — 보관해야 하는 것에는 일회용 워크스페이스를 사용하지 마세요.

워크스페이스를 재사용 가능한 베이스 이미지로 만들려면 어떻게 하나요?

워크스페이스를 중지한 뒤, 중지된 워크스페이스에 표시되는 배너에서 베이스 이미지로 저장 을 선택하세요. 나중에 같은 워크스페이스를 다시 저장하면 이전 이미지를 덮어쓰는 대신 새롭고 독립적인 베이스 이미지가 생성됩니다 — 더 이상 필요 없는 베이스 이미지는 환경설정 → 베이스 이미지에서 관리하고 삭제할 수 있습니다.

제 워크스페이스와 베이스 이미지는 어디에 저장되며, 공간을 확보하려면 어떻게 하나요?

워크스페이스 디스크와 베이스 이미지는 Mac의 ~/Library/Application Support/VeloWorkspaces 에 저장됩니다. 공간을 확보하려면 라이브러리에서 더 이상 필요 없는 워크스페이스를, 환경설정 → 베이스 이미지에서 사용하지 않는 베이스 이미지를 삭제하세요.

일반

Velo Workspaces가 Windows 게스트를 지원하나요?

이번 릴리스에서는 지원하지 않습니다. Velo Workspaces는 현재 Linux와 macOS 게스트를 지원합니다.

워크스페이스가 실행 중일 때 일부 설정을 변경할 수 없는 이유는 무엇인가요?

CPU, 메모리, 스토리지, 공유 폴더 등 몇 가지 설정은 가상 머신 구성의 일부이며 실행 중에는 변경할 수 없습니다(Apple의 Virtualization 프레임워크는 이를 핫플러그로 지원하지 않습니다). 워크스페이스를 중지하고 변경한 뒤 다시 시작하세요.

macOS 게스트를 만들 수 없는 이유는 무엇인가요?

macOS 게스트는 호스트로 Apple 실리콘 Mac이 필요합니다. Intel Mac에서는 Linux 게스트가 여전히 완전히 지원됩니다.
