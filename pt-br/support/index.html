Primeiros passos

Como criar um workspace

  1. Abra Novo Workspace

    Na biblioteca de workspaces, escolha Novo Workspace e selecione uma fonte de imagem: uma imagem oficial, um disco virtual existente, ou uma imagem base salva.

  2. Escolha um perfil

    Escolha o perfil que combina com seu trabalho — Código e Build, Lab DevOps, Sandbox de IA, e mais — ou configure CPU, memória e armazenamento você mesmo.

  3. Revise e inicie

    Confirme o resumo e inicie a instalação (ou o boot, no caso de um clone de imagem base). Imagens oficiais são baixadas diretamente da fonte oficial daquele projeto na primeira vez que você as usa.

Como usar workspaces descartáveis

  1. Marcar um workspace como descartável

    Ao criar um workspace, ative a opção descartável — combina melhor com uma imagem base, para que ele inicie instantaneamente a partir de um estado conhecido e funcional.

  2. Use para exatamente uma tarefa

    Rode seu teste, reproduza o bug, ou experimente o comando arriscado — trate o workspace como totalmente descartável.

  3. Feche-o

    Fechar um workspace descartável o exclui automaticamente, disco incluído. Não há nada para limpar depois, e nada para recuperar — não use workspaces descartáveis para nada que você precise manter.

Perguntas frequentes

Pastas compartilhadas

Como acesso a pasta compartilhada de dentro de um workspace?

Workspaces macOS (macOS 13 ou posterior): pastas compartilhadas são montadas automaticamente — abra o Finder e procure em /Volumes/My Shared Files. Nenhum comando necessário.

Workspaces Linux: cada pasta compartilhada tem seu próprio comando de montagem, mostrado diretamente no app na aba Arquivos Compartilhados do workspace. Fica assim, usando a própria tag daquela pasta:

mkdir -p /mnt/my_folder
sudo mount -t virtiofs <folder-tag-shown-in-app> /mnt/my_folder

Use exatamente a tag mostrada no app — ela é única por pasta, então copiar um comando de outro lugar não vai funcionar.

Área de transferência e entrada

Copiar e colar não funciona entre meu Mac e um workspace Linux

O compartilhamento da área de transferência no Linux depende de um agente rodando dentro do convidado. Siga estes passos em ordem:

  1. Na aba Recursos do workspace, confirme que Compartilhamento de Área de Transferência está ativado.
  2. Dentro do convidado, confirme que o spice-vdagent está instalado: 
    sudo apt install spice-vdagent
  3. Confirme que o agente está realmente rodando: 
    systemctl status spice-vdagentd
    Se estiver inativo, inicie-o com sudo systemctl start spice-vdagentd, e, se você estiver em um desktop gráfico, saia e entre novamente para que a sessão desktop reconheça.
  4. Alguns ambientes desktop mínimos ou headless não iniciam o spice-vdagent automaticamente — verifique as configurações de inicialização automática do seu ambiente desktop se ainda não funcionar depois que o agente estiver instalado e rodando.

O compartilhamento da área de transferência atualmente funciona apenas para workspaces Linux.

Rosetta (x86_64 no Apple Silicon)

Como ativo o Rosetta em um workspace Debian?

O Debian usa as mesmas ferramentas apt e update-binfmts que o Ubuntu. Ative o Rosetta para o workspace na aba Recursos, inicie o workspace, e execute isto uma vez dentro do convidado:

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo apt-get update
sudo apt-get install -y binfmt-support

sudo /usr/sbin/update-binfmts --install rosetta /media/rosetta/rosetta \
  --magic "\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00" \
  --mask "\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff" \
  --credentials yes --preserve yes --fix-binary yes
Como ativo o Rosetta em um workspace Fedora?

O Fedora não vem com a ferramenta update-binfmts do Debian, mas vem com o systemd-binfmt, que lê exatamente o mesmo registro de kernel binfmt_misc a partir de um arquivo de configuração. Ative o Rosetta para o workspace na aba Recursos, inicie o workspace, e execute isto uma vez dentro do convidado:

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo mkdir -p /etc/binfmt.d
sudo tee /etc/binfmt.d/rosetta.conf > /dev/null <<'EOF'
:rosetta:M::\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00:\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff:/media/rosetta/rosetta:CF
EOF

sudo systemctl restart systemd-binfmt

O arquivo rosetta.conf persiste entre reinicializações, então é uma configuração única por workspace.

Ponte de IA

Como conecto a Ponte de IA ao Ollama?
  1. Instale e execute o Ollama no seu Mac, fora do workspace.
  2. Ative a Ponte de IA para o workspace (ativa por padrão no perfil Sandbox de IA, ou ative você mesmo nas configurações de Integrações ou Recursos do workspace).
  3. Inicie o workspace e abra sua aba Ponte de IA — ela mostra o endereço do endpoint local e, para um convidado Linux, os comandos exatos para encaminhar a conexão.
  4. Dentro do workspace, aponte suas ferramentas para esse endereço, exatamente como você faria com qualquer servidor local que use o formato de API chat-completions padrão.

Workspaces descartáveis e imagens base

O que acontece com um workspace descartável quando eu o fecho?

Ele é excluído automaticamente no momento em que você o fecha, disco incluído. Não há nada para recuperar depois — não use um workspace descartável para nada que você precise manter.

Como transformo um workspace em uma imagem base reutilizável?

Pare o workspace e escolha Salvar como Imagem Base no banner mostrado em um workspace parado. Salvar o mesmo workspace novamente depois cria uma nova imagem base independente, em vez de sobrescrever a anterior — gerencie e exclua imagens base que você não precisa mais em Preferências → Imagens Base.

Onde meus workspaces e imagens base são armazenados, e como libero espaço?

Discos de workspace e imagens base ficam em ~/Library/Application Support/VeloWorkspaces no seu Mac. Exclua da biblioteca os workspaces que você não precisa mais, e imagens base não usadas em Preferências → Imagens Base, para liberar espaço.

Geral

O Velo Workspaces suporta convidados Windows?

Não nesta versão. O Velo Workspaces atualmente suporta convidados Linux e macOS.

Por que não consigo alterar algumas configurações enquanto um workspace está em execução?

CPU, memória, armazenamento, pastas compartilhadas e algumas outras configurações fazem parte da configuração da máquina virtual e não podem ser alteradas enquanto ela está em execução (o framework Virtualization da Apple não suporta hot-plugging delas). Pare o workspace, faça a alteração, e inicie-o novamente.

Por que não consigo criar um convidado macOS?

Convidados macOS exigem um Mac com Apple Silicon como host. Em um Mac Intel, convidados Linux continuam totalmente suportados.
