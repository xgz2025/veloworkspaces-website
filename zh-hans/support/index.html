入门指南

如何创建工作区

  1. 选择系统来源

    在侧边栏选择一个库，然后点击右上角的「+」。想要约一分钟就能用的现成系统，选「云镜像」；想运行发行版自带的安装程序，选「安装镜像」；想从基础镜像或已有磁盘开始，选「从现有虚拟磁盘启动」。

  2. 选择镜像

    选择发行版和版本。镜像从发行方自己的服务器下载到你的镜像库，用官方公布的校验和验证，下次直接复用。已经有文件了？点击「选择文件…」。对于 Ubuntu、Fedora Server 和 Rocky Linux 的安装程序，保持「自动安装」开启，安装就会自己完成。

  3. 配置、确认并创建

    选择一个预设（Code & Build、DevOps Lab、AI Sandbox 或 Office & Study），或自行设置 CPU、内存和磁盘，然后输入用户名和密码。确认摘要后点击「创建工作区」。App 会为你创建账户，并加入这台 Mac 的 SSH 密钥。

如何使用用后即焚工作区Pro

  1. 添加用后即焚工作区

    在侧边栏选择「用后即焚工作区」，点击右上角的「+」，按上面的步骤操作。最快的方式是用已保存的基础镜像「从现有虚拟磁盘启动」：一个已验证可用的系统，几秒就能运行。

  2. 仅用于一项任务

    运行你的测试、复现 bug，或尝试有风险的命令——把这个工作区当作完全可以丢弃的对象。

  3. 关闭它

    关闭一个用后即焚工作区会自动将其删除，包括磁盘在内。之后无需清理，也无法恢复——不要把用后即焚工作区用于任何你需要保留的东西。

常见问题

云镜像与自动安装

哪些 Linux 可以用云镜像创建？

Ubuntu 26.04 和 24.04 LTS、Debian 13 和 12、Fedora 44 Cloud Base，以及 Rocky Linux 10 和 9。App 会下载发行方的官方镜像，转换为 Apple Virtualization 框架可用的格式，并把用户名、密码、这台 Mac 的 SSH 密钥和主机名交给 cloud-init。首次启动时系统会自行完成设置，并扩展到你选择的磁盘大小。下载完成后，通常约一分钟就能登录。

哪些安装程序可以自动完成？

Ubuntu Server 和 Desktop、Fedora Server 和 Everything，以及 Rocky Linux（minimal 和 DVD）。在「镜像」步骤保持「自动安装」开启，App 会替你回答安装程序的问题：你的账户和 SSH 密钥，以及这台 Mac 的语言、键盘和时区。安装程序不会中途提问，清空虚拟磁盘前也不会要求确认。安装完成后，工作区会重启进入新系统。

哪些系统需要手动安装？

Debian 安装程序、Fedora Workstation、Kali Linux、NixOS 和 Alpine Linux 会在工作区的显示画面中运行各自的安装程序，和在 PC 上一样。想要免手动的 Debian，请改用 Debian 云镜像。在搭载 Apple 芯片的 Mac 上，还可以用 Apple 的恢复镜像安装 macOS。

能用已经下载好的 ISO 或云镜像吗？

可以。在「镜像」步骤点击 选择文件… ，或在「设置 › 镜像」中点击「导入…」。如果文件名出现在发行方的校验和列表中，App 会在使用前用官方校验和验证它。下载或导入的镜像都会保留在「设置 › 镜像」中（侧边栏的「镜像」也能打开），可以复用、验证或删除。

SSH 与终端

如何在工作区中打开终端？Pro

启动工作区，打开它的「访问」标签页，点击「打开终端」。内置终端会用 App 为这台 Mac 生成并保存在钥匙串中的密钥通过 SSH 登录。用云镜像或自动安装创建的工作区已经信任这个密钥。

如果是你自己安装的系统，请在「访问」标签页输入用户名，用密码登录一次，然后点击「安装密钥」，之后就不再需要密码。你可以在「设置 › 访问」中复制、导入或导出密钥。

可以用自己的终端或 VS Code，或从另一台电脑连接吗？

可以，而且免费。「访问」标签页会显示工作区的地址和可直接复制的 ssh 命令，以及供 VS Code Remote - SSH 扩展使用的 ~/.ssh/config 配置块。它们使用的是你自己的 SSH 密钥，而不是内置终端保存在钥匙串中的那把。创建工作区时，请在「SSH 公钥」中粘贴你的公钥，或打开「允许使用密码进行 SSH 登录」。

工作区位于 Mac 内部的私有网络中，其他电脑需要经由你的 Mac 连接。在「系统设置 › 通用 › 共享」中打开「远程登录」，然后使用「访问」标签页中显示的 ssh -J 命令。

为什么 macOS 询问是否允许 Velo Workspaces 查找本地网络上的设备？

工作区位于 Mac 内部的一个小型虚拟网络中（地址类似 192.168.64.x），macOS 把它算作本地网络。SSH 检查和终端会连接这个地址，所以 macOS 会询问一次。App 从不浏览或扫描你的网络，只连接它自己的工作区。

如果你选了「不允许」，「访问」标签页会显示「无本地网络访问权限」。请在「系统设置 › 隐私与安全性 › 本地网络」中重新打开。

共享文件夹

如何从工作区内部访问共享文件夹？

macOS 工作区（macOS 13 或更高版本）：共享文件夹会自动挂载——打开访达（Finder），查看 /Volumes/My Shared Files路径下的内容。无需任何命令。

Linux 工作区：每个共享文件夹都有自己的挂载命令，会直接显示在应用内该工作区的「共享文件」标签页中，使用该文件夹专属的标签，形如：

mkdir -p /mnt/my_folder
sudo mount -t virtiofs <folder-tag-shown-in-app> /mnt/my_folder

请使用应用中显示的确切标签——每个文件夹的标签都是唯一的，因此从别处复制的命令不会生效。

剪贴板与输入

Mac 与 Linux 工作区之间的复制粘贴不生效

Linux 上的剪贴板共享依赖于虚拟机内运行的代理程序。请按顺序检查以下几点：

  1. 在工作区的「资源」标签页中，确认 剪贴板共享 已打开。
  2. 在虚拟机内，确认 spice-vdagent 已安装： 
    sudo apt install spice-vdagent
  3. 确认该代理程序确实在运行： 
    systemctl status spice-vdagentd
    如果处于未激活状态，用 sudo systemctl start spice-vdagentd启动它；如果你使用的是图形桌面环境，请注销后重新登录，以便桌面会话识别它。
  4. 某些精简版或无图形界面的桌面环境不会自动启动 spice-vdagent ——如果代理程序已安装并运行，但仍然不生效，请检查你桌面环境的自启动设置。

剪贴板共享目前仅适用于 Linux 工作区。

Rosetta（在 Apple 芯片上运行 x86_64）Pro

如何在 Debian 工作区中启用 Rosetta？

Debian 使用与 Ubuntu 相同的 apt 和 update-binfmts 工具。在工作区的「资源」标签页中打开 Rosetta，启动该工作区，然后在虚拟机内执行一次以下命令：

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo apt-get update
sudo apt-get install -y binfmt-support

sudo /usr/sbin/update-binfmts --install rosetta /media/rosetta/rosetta \
  --magic "\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00" \
  --mask "\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff" \
  --credentials yes --preserve yes --fix-binary yes
如何在 Fedora 工作区中启用 Rosetta？

Fedora 没有自带 Debian 的 update-binfmts 工具，但自带了 systemd-binfmt，它会从配置文件中读取与前者完全相同的内核 binfmt_misc 注册信息。在工作区的「资源」标签页中打开 Rosetta，启动该工作区，然后在虚拟机内执行一次以下命令：

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo mkdir -p /etc/binfmt.d
sudo tee /etc/binfmt.d/rosetta.conf > /dev/null <<'EOF'
:rosetta:M::\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00:\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff:/media/rosetta/rosetta:CF
EOF

sudo systemctl restart systemd-binfmt

rosetta.conf 文件会在重启后依然保留，因此每个工作区只需设置一次。

AI 桥接Pro

如何将 AI 桥接连接到 Ollama 或 MLX？
  1. 在工作区之外，于你的 Mac 上安装并运行 Ollama 或 MLX。
  2. 为该工作区启用 AI 桥接（在 AI 沙盒预设中默认开启，也可以自行在工作区的「集成」或「资源」设置中打开）。
  3. 启动工作区，然后打开它的 AI 桥接标签页——其中会显示本地端点地址，对于 Linux 虚拟机，还会显示转发连接所需的确切命令。
  4. 在工作区内，把你的工具指向这个地址，就像连接任何使用标准 chat-completions API 格式的本地服务器一样。

诊断

如何导出日志以排查问题？

从侧边栏打开「诊断」，然后点击「导出」。这会将本地应用日志和系统信息打包成 Mac 上的一个文件——便于在与我们排查问题时附加到邮件中。

系统绝不会自动收集任何内容。该导出操作只有在你自己执行时才会发生，生成的文件会保留在你的 Mac 上，除非你选择发送它。

用后即焚工作区与基础镜像

关闭用后即焚工作区后会发生什么？

关闭的瞬间它会被自动删除，包括其磁盘。之后无法恢复——不要把用后即焚工作区用于任何你需要保留的东西。

如何把一个工作区变成可复用的基础镜像？Pro

停止该工作区，然后在已停止工作区显示的横幅中选择 保存为基础镜像 。之后再次保存同一个工作区，会创建一个新的独立基础镜像，旧的仍然保留。可以在「设置 › 镜像 › 基础镜像」中管理和删除基础镜像。

工作区和镜像存放在哪里？如何释放空间？

工作区磁盘和基础镜像存放在你 Mac 上的 ~/Library/Application Support/VeloWorkspaces 目录下。要释放空间，请从库中删除不再需要的工作区，并在「设置 › 镜像」中删除不再使用的已下载镜像或基础镜像。

常规问题

Velo Workspaces 支持 Windows 虚拟机吗？

此版本尚不支持。Velo Workspaces 目前支持 Linux 和 macOS 虚拟机。

为什么工作区运行时无法更改某些设置？

CPU、内存、存储、共享文件夹等一些设置属于虚拟机配置的一部分，运行期间无法更改（Apple 的 Virtualization 框架不支持对这些项目进行热插拔）。请先停止该工作区，完成更改后再重新启动。

为什么我无法创建 macOS 虚拟机？

创建 macOS 虚拟机需要以 Apple 芯片 Mac 作为主机。在 Intel Mac 上，Linux 虚拟机仍然完全受支持。

从 Ubuntu Server（最小化安装）基础镜像克隆的工作空间无法获取 IP 地址

Velo Workspaces 会为每个工作空间分配一个新的唯一 MAC 地址，包括从基础镜像克隆出的工作空间。Ubuntu Server 的最小化安装默认在 systemd-networkd 之上使用 Netplan 配置网络，它默认会将网络接口绑定到基础镜像原本的 MAC 地址，而不是按接口名称匹配——因此一旦克隆后的 MAC 地址发生变化，配置就不再匹配，也就永远不会发起 DHCP 请求。

找到工作空间实际的 MAC 地址，然后更新到 netplan 的配置文件中：

ip addr show

记下该网络接口（通常是 enp0s1）link/ether 后显示的地址，将其设置为 netplan 配置中该接口的 MAC 地址，然后重新应用：

sudo sed -i 's/macaddress:.*/macaddress: <new-mac-address>/' /etc/netplan/*.yaml
sudo netplan apply
