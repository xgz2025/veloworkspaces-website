Primeros pasos

Cómo crear un espacio de trabajo

  1. Abrir Nuevo espacio de trabajo

    Desde la biblioteca de espacios de trabajo, elige Nuevo espacio de trabajo y selecciona una fuente de imagen: una imagen oficial, un disco virtual existente, o una imagen base guardada.

  2. Elegir un perfil

    Elige el perfil que se ajuste a tu trabajo — Código y compilación, Laboratorio DevOps, Sandbox de IA, y más — o configura tú mismo CPU, memoria y almacenamiento.

  3. Revisar y lanzar

    Confirma el resumen y luego inicia la instalación (o el arranque, para un clon de una imagen base). Las imágenes oficiales se descargan directamente desde la fuente propia de ese proyecto la primera vez que las usas.

Cómo usar los espacios de trabajo desechables

  1. Marcar un espacio de trabajo como desechable

    Al crear un espacio de trabajo, activa la opción desechable — lo ideal es combinarla con una imagen base para que arranque al instante desde un estado conocido y funcional.

  2. Úsalo para exactamente una tarea

    Ejecuta tu prueba, reproduce el error, o prueba el comando arriesgado — trata el espacio de trabajo como totalmente prescindible.

  3. Ciérralo

    Cerrar un espacio de trabajo desechable lo elimina automáticamente, disco incluido. No hay nada que limpiar después, ni nada que recuperar — no uses espacios de trabajo desechables para nada que necesites conservar.

Preguntas frecuentes

Carpetas compartidas

¿Cómo accedo a la carpeta compartida desde dentro de un espacio de trabajo?

Espacios de trabajo macOS (macOS 13 o posterior): las carpetas compartidas se montan automáticamente — abre Finder y busca en /Volumes/My Shared Files. No se necesita ningún comando.

Espacios de trabajo Linux: cada carpeta compartida tiene su propio comando de montaje, que se muestra directamente en la app en la pestaña Archivos compartidos del espacio de trabajo. Se ve así, usando la etiqueta propia de esa carpeta:

mkdir -p /mnt/my_folder
sudo mount -t virtiofs <folder-tag-shown-in-app> /mnt/my_folder

Usa exactamente la etiqueta mostrada en la app — es única por carpeta, así que copiar un comando de otro lugar no funcionará.

Portapapeles y entrada

Copiar y pegar no funciona entre mi Mac y un espacio de trabajo Linux

La compartición del portapapeles en Linux depende de un agente que se ejecuta dentro del invitado. Sigue estos pasos en orden:

  1. En la pestaña Recursos del espacio de trabajo, confirma que Compartir portapapeles esté activado.
  2. Dentro del invitado, asegúrate de que spice-vdagent esté instalado: 
    sudo apt install spice-vdagent
  3. Confirma que el agente realmente se esté ejecutando: 
    systemctl status spice-vdagentd
    Si está inactivo, inícialo con sudo systemctl start spice-vdagentd, y si usas un escritorio gráfico, cierra sesión y vuelve a entrar para que la sesión de escritorio lo reconozca.
  4. Algunos entornos de escritorio mínimos o headless no inician spice-vdagent automáticamente — revisa la configuración de inicio automático de tu entorno de escritorio si sigue sin funcionar después de que el agente esté instalado y en ejecución.

La compartición del portapapeles actualmente solo funciona para espacios de trabajo Linux.

Rosetta (x86_64 en Apple Silicon)

¿Cómo activo Rosetta en un espacio de trabajo Debian?

Debian usa las mismas herramientas apt y update-binfmts que Ubuntu. Activa Rosetta para el espacio de trabajo en su pestaña Recursos, inícialo, y luego ejecuta esto una vez dentro del invitado:

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo apt-get update
sudo apt-get install -y binfmt-support

sudo /usr/sbin/update-binfmts --install rosetta /media/rosetta/rosetta \
  --magic "\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00" \
  --mask "\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff" \
  --credentials yes --preserve yes --fix-binary yes
¿Cómo activo Rosetta en un espacio de trabajo Fedora?

Fedora no incluye la herramienta update-binfmts de Debian, pero sí incluye systemd-binfmt, que lee exactamente el mismo registro del kernel binfmt_misc desde un archivo de configuración. Activa Rosetta para el espacio de trabajo en su pestaña Recursos, inícialo, y luego ejecuta esto una vez dentro del invitado:

sudo mkdir -p /media/rosetta
sudo mount -t virtiofs rosetta /media/rosetta

sudo mkdir -p /etc/binfmt.d
sudo tee /etc/binfmt.d/rosetta.conf > /dev/null <<'EOF'
:rosetta:M::\x7fELF\x02\x01\x01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x3e\x00:\xff\xff\xff\xff\xff\xfe\xfe\x00\xff\xff\xff\xff\xff\xff\xff\xff\xfe\xff\xff\xff:/media/rosetta/rosetta:CF
EOF

sudo systemctl restart systemd-binfmt

El archivo rosetta.conf persiste entre reinicios, así que es una configuración única por espacio de trabajo.

Puente de IA

¿Cómo conecto Puente de IA a Ollama?
  1. Instala y ejecuta Ollama en tu Mac, fuera del espacio de trabajo.
  2. Activa Puente de IA para el espacio de trabajo (activado por defecto en el perfil Sandbox de IA, o actívalo tú mismo en la configuración de Integraciones o Recursos del espacio de trabajo).
  3. Inicia el espacio de trabajo y luego abre su pestaña Puente de IA — muestra la dirección del endpoint local y, para un invitado Linux, los comandos exactos para reenviar la conexión.
  4. Dentro del espacio de trabajo, apunta tus herramientas a esa dirección igual que lo harías con cualquier servidor local que use el formato de API chat-completions estándar.

Espacios de trabajo desechables e imágenes base

¿Qué pasa con un espacio de trabajo desechable cuando lo cierro?

Se elimina automáticamente en el momento en que lo cierras, disco incluido. No hay nada que recuperar después — no uses un espacio de trabajo desechable para nada que necesites conservar.

¿Cómo convierto un espacio de trabajo en una imagen base reutilizable?

Detén el espacio de trabajo y luego elige Guardar como imagen base desde el banner que se muestra en un espacio de trabajo detenido. Guardar el mismo espacio de trabajo de nuevo más tarde crea una nueva imagen base independiente en lugar de sobrescribir la anterior — gestiona y elimina las imágenes base que ya no necesites desde Preferencias → Imágenes base.

¿Dónde se almacenan mis espacios de trabajo e imágenes base, y cómo libero espacio?

Los discos de los espacios de trabajo y las imágenes base están en ~/Library/Application Support/VeloWorkspaces en tu Mac. Elimina de la biblioteca los espacios de trabajo que ya no necesites, y las imágenes base sin usar desde Preferencias → Imágenes base, para liberar espacio.

General

¿Velo Workspaces admite invitados Windows?

No en esta versión. Velo Workspaces actualmente admite invitados Linux y macOS.

¿Por qué no puedo cambiar algunos ajustes mientras un espacio de trabajo está en ejecución?

CPU, memoria, almacenamiento, carpetas compartidas y algunos otros ajustes forman parte de la configuración de la máquina virtual y no se pueden cambiar mientras está en ejecución (el framework Virtualization de Apple no admite modificarlos en caliente). Detén el espacio de trabajo, haz el cambio, y vuelve a iniciarlo.

¿Por qué no puedo crear un invitado macOS?

Los invitados macOS requieren un Mac con Apple Silicon como host. En un Mac Intel, los invitados Linux siguen siendo totalmente compatibles.
